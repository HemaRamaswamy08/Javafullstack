How the ArrayList works
The ArrayList class has a regular array inside it. When an element is added, it is placed into the array. If the array is not big enough, a new, larger array is created to replace the old one and the old one is removed.
	

b} LinkedList
	->The LinkedList class is a collection which can contain many objects of the same type, just like the ArrayList.
	-> intouduced from 1.2 , implements List, Deque, Cloneable, java.io.Serializable
	-> Underlying data structure is Doubly linked list (Node = previous node addrs - data - next node addres)

How the LinkedList works
The LinkedList stores its elements in "containers." The list has a link to the first container and each container has a link to the next container in the list. To add an element to the list, the element is placed into a new container and that container is linked to one of the other containers in the list.
USE -  to manipulate data. like insertion and deletion

It is is a implenentation of Linked list data structure which is a linear data structure where the elements are not stored in contiguous locations, and every element is a separate object with a data part and an address part.
The elements are linked using pointers and addresses, and each element is known as a node.
A node cannot be acessed directly , we have to start from head and follow the link untill its found

methods : addFirst()	->Adds an element to the beginning of the list	
	addLast() ->	Add an element to the end of the list	
	removeFirst()	->Remove an element from the beginning of the list	
	removeLast()	->Remove an element from the end of the list	
	getFirst()	->Get the element at the beginning of the list	
	getLast() ->	Get the element at the end of the list

advantage and disadvantage
->we can increase or decrease it's size whenever we need, so there is no need to set the size of a linkedlist before using it.
->Adding or removing elements in the middle of a linkedlist is a very simple task. We just need to change the links between nodes without moving other element
->we can move in forward and backward direction

->finding an element is time consuming
->each elemet has extra memory so takes more memory

In java Collection is introduced in version 1.2 and iterable  introduced in 1.5 but how come collection extends interable interface??

1.  Backward Compatibility and Re-architecting:
		 When Java 1.5 was released, it introduced Generics and the enhanced `for-each` loop. To make the `for-each` loop work with existing collection types (like `List`, `Set`, etc., which were already part of the `Collection` hierarchy), a new mechanism was needed.

2.  The Role of `Iterable`:The `Iterable` interface was specifically designed to enable the `for-each` loop. Any class that implements `Iterable` (and thus provides an `iterator()` method) can be used with the `for-each` loop.

3.  Retrofitting `Collection`: Instead of forcing all existing `Collection` implementations to be rewritten to directly implement `Iterable`, the Java designers took a more elegant approach: they made the `Collection` interface itself extend `Iterable`.

    Prior to Java 1.5: The `Collection` interface (and its sub-interfaces like `List` and `Set`) already had an `iterator()` method. This method was part of the original design for iterating through collections using an `Iterator` object.
