Marker Interface 

Marker interfaces in Java are interfaces with no methods or members. 
They serve as a “marker” to the compiler or runtime environment, indicating that a class implementing the interface should be treated differently or has some special behavior. There are 3 types in marker interface : serializable , clonable and r

1 . Serializable:
Functionality: 
	Indicates that objects of a class can be serialized, meaning they can be converted into a byte stream for storage or transmission.
Uses: 
	Used in I/O operations where objects need to be serialized, such as storing objects in files or sending them over the network.
Example:
	One real-life example where the Serializable interface is commonly used is in the context of saving and loading objects to and from files in Java applications. 

	 // Create a UserProfile object
        UserProfile userProfile = new UserProfile("JohnDoe", "johndoe@example.com", 25);
        // Save the UserProfile object to a file
        try (ObjectOutputStream outputStream = new ObjectOutputStream(new FileOutputStream("userprofile.dat"))) {
            outputStream.writeObject(userProfile);
            System.out.println("User profile saved successfully.");
        } catch (IOException e) {
            e.printStackTrace();
        }
        // Load the UserProfile object from the file
        try (ObjectInputStream inputStream = new ObjectInputStream(new FileInputStream("userprofile.dat"))) {
            UserProfile loadedProfile = (UserProfile) inputStream.readObject();
            System.out.println("Loaded user profile: " + loadedProfile.getUsername() + ", " + loadedProfile.getEmail() + ", " + loadedProfile.getAge());
        } catch (IOException | ClassNotFoundException e) {
            e.printStackTrace();
        }

explinatation : 
	->We create a UserProfile object with some sample data.
	->We use ObjectOutputStream to serialize the UserProfile object and save it to a file named "userprofile.dat".
	->We use ObjectInputStream to deserialize the UserProfile object from the file and load it back into memory.
	-> The Serializable interface allows us to easily save the UserProfile object to a file and load it back without having to 			      manually convert its attributes to a byte stream. It simplifies the process of persistence and data storage in Java applications.

Cloneable:

Functionality: 
	Indicates that objects of a class can be cloned, meaning they can create a copy of themselves.
Uses: 
	Used when implementing custom cloning logic for objects, though it’s recommended to use clone() method carefully due to shallow copying.
Example:
	One real-life example where the Cloneable interface might be used is in the context of creating copies of objects, such as when dealing with prototypes or templates. Let's consider an example of a prototype for a car configuration in an automobile manufacturing application:
	@Override
	 public CarConfiguration clone() {
        try {
            return (CarConfiguration) super.clone();
        } catch (CloneNotSupportedException e) {
            // This should never happen since CarConfiguration implements Cloneable
            throw new AssertionError();
        }
    }

RandomAccess:

Functionality:
	 Indicates that a class supports efficient random access to its elements, typically through index-based access.
Uses:
	 Used to optimize algorithms or operations that require random access to elements in a collection, such as searching or sorting
example : 
	the ArrayList performs random access operations much faster than the LinkedList. This is because ArrayList implements the RandomAccess interface, indicating that it provides efficient random access to its elements through index-based access.
