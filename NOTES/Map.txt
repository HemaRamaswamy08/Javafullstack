											MAP (1.2)

-> It is not a part of Collections
->No Duplicates in Keys: Keys should be unique, but values can be duplicated.
->Allows only one null as key in hashMap , linkedHashMap
->The three primary classes that implement these interfaces are,
	HashMap
	TreeMap
	LinkedHashMap

1.HashMap
	->Internally uses Hashing (similar to Hashtable in Java).
	->from 1.2 present in java.util
	->One null Key and Many null alues can be used
	->Keys and value can't be primitive datatype.  Key in Hashmap is valid if it implements hashCode() and equals() method , it should also be immutable (immutable custom object ) so that hashcode and equality remains constant.
	-> implements Serializable, Cloneable,
	-> HashMaps are not ordered, 
	->HashMaps are not thread-safe,
	-> initial capacity of 16 ( 2^4=16) and a load factor of 0.75.( Load Factor - It is the percent value of the capacity after which the capacity of Hashmap is to be increased)
	->Threshold - It is the product of Load Factor and Initial Capacity. In java, by default, it is (16 * 0.75 = 12). That is, Rehashing takes place after inserting 12 key-value pairs into the HashMap.
	->Rehashing - It is the process of doubling the capacity of the HashMap after it reaches its Threshold .(2^4, 2^5, 2^6, 2^7, ..)
	->From Java 8 onward, Java has started using Self Balancing BST instead of a linked list for chaining
	-> retrieval and insertion of elements is very fast.
	->Unordered, HIgh memory usgae 
	->Performance can degrade: only if the hashing function is not properly implemented or if the load factor is too high
	->More complex than arrays or lists
	->Internally HashMap contains an array of Node and a node is represented as a class that contains 4 fields:  int hash , K key , V value, Node next
	->performance of HashMap depends on 2 parameters  : Initial Capacity , LOad factor	


2.LinkedHashMap
->stores key-value pairs while maintaining the insertion order of the entries.
-> LinkedHashMap Class is just like HashMap with an additional feature of maintaining an order of elements inserted into it.
->the data is stored in the form of nodes. The implementation of the LinkedHashMap is very similar to a doubly-linked list. Therefore, each node of the LinkedHashMap is represented as:  Before : Key : Value : After

3.TreeMap
-> It implementas  NavigableMap Interface (from 1.6)   which is further  extends SortedMap interface(from 1.2)
->It stores key-value pairs in a sorted order based on the natural ordering of keys or a custom Comparator
->It uses a Red-Black Tree for efficient operations (add, remove, retrieve) with a time complexity of O(log n).
	->The keys in a TreeMap are always sorted.
	->Does not allow Null as Key but as a values is allowed . Attempting to insert a null key will result in NullPointerException.
	->They do not support the Entry.setValue method.
	-> TreeMap is not synchronized by default , we need to synchronize it externally. This is typically done using the Collections.synchronizedSortedMap() method.
		 map itself is synchronized now but still , we may still need to handle synchronization when iterating over the map, as the iterator is not thread-safe.
